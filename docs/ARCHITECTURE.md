# 架构与设计

## 数据流

```text
日志文件 -> reader / parser -> 成功记录与输入错误
                         -> stats
                         -> detector（精确配置路径）
                         -> behavior（UTC 排序、每 IP 滑动窗口）
                         -> 统一分析报告
                         -> 可选 privacy 分享视图
                         -> JSON 或 report Markdown
```

读取、分析和展示分离。分析器不联网、不执行日志中的表达式、不调用 shell、不自动封禁。只有显式运行 run_experiment.py 才会建立本机回环 HTTP 服务。

## 输入质量

reader 保留原文件行号和去换行后的 raw；raw 不是逐字节归档。UTF-8-sig 兼容 BOM。空行单独计数，结构错误保留原因，无效时间保留在基础统计中但排除出时间窗口。原日志仍需独立保存。

计数核对：总行数 = 成功数 + 结构错误数 + 空行数。

## 路径策略

target 保留原样。统计和检测只移除第一个问号之后的查询串；不自动 URL 解码、转小写或规范化斜杠。/a%2Fb 与 /a/b 保持不同。仅支持常见 origin-form 请求路径，绝对 URI 等不做通用标准化。避免未经定义的归一化改变证据；代价是明确的漏报边界。

## 时间窗口

按来源 IP 分组，再按带时区时间转 UTC 排序，相同时间按原始行号排序。窗口为闭区间 [当前时间-W, 当前时间]，使用 deque 和 Counter 移除过期请求并维护不同路径数。

每个 IP 只报告首个满足阈值的窗口，避免告警爆炸，不代表后续行为没有发生。路径去重但证据不去重，窗口请求数可能大于路径数。整体排序约 O(n log n)，窗口扫描约 O(n)；没有大文件性能验收。

## 配置

默认配置相对 analyze.py 定位，不依赖 cwd。--config 指定完整配置；显式命令行阈值优先。拒绝未知/缺失字段、重复键、错误类型、非法路径。空敏感路径数组只关闭精确匹配。默认文件失效时明确失败，不静默退回。

## 导出

默认 JSON schema_version=1.1。可选 configuration/privacy 为扩展字段。Markdown 是统一数据的视图，不再检测。动态日志字段只进入缩进代码块，不直接拼接成 HTML、链接或标题。输出使用独占创建，拒绝覆盖旧报告或输入文件。写盘中断仍可能留下部分文件，应检查退出状态和内容；当前不承诺事务写入。

## 受控实验

HTTPServer 只绑定 127.0.0.1 动态端口，固定文本路由，不暴露文件系统。http.client 直连避免代理污染。真实接收请求后生成 combined 结构日志；不是原生 Nginx。关闭服务并验证端口后保留证据。一键实验固定自己的配置快照，不受用户修改默认配置影响。

## 未实现

HTTPS 流量还原、WAF、实时采集、可信代理、自动封禁、Nginx 原生适配测试、自动判定入侵成功、生产精度与容量评估。当前功能边界是离线辅助排查。
