# WebLogLens 3.0.0 发布说明

## 相比第二版

1. 接入：约定 Nginx JSON 与有界预检，保留 combined 默认和旧批量入口。
2. 隔离：每站点独立窗口、水位、冷却与 idle，容量有上限且排除明确留证。
3. 回查：SQLite 派生索引、条件查询、来源时间线；不需要数据库服务器，不把已有线索引用当成新请求。
4. 运行：可选完整行分片、默认不删的保留策略、完整性校验拼接；周期与退出健康状态。
5. 交付：主文档统一第三版，保留旧包，白名单打包和中文路径/非 cwd 复验。

项目为个人实践，AI 辅助开发。主要价值是可解释排查和可靠留证，不是检测规则数量、数据库选型或大屏。

## 兼容与使用

Python 标准库，无新增 pip 依赖；实机覆盖 Windows Python 3.11.9 与 3.15.1。analyze 仍只支持 combined；watch 默认 combined，JSON 需显式 --log-format nginx-json。单文件 --output 不变，滚动为可选项。分片须完整拼接后才导入/汇总；显式删除旧片会失去整次完整导出能力。

具体命令见 QUICKSTART 和 V3-RUNTIME。样例站点 a.local/b.local 是配置标签，不需公网访问。核心运行不需 Docker，真实 Nginx 实验需要本地已有镜像。

## 实测边界

本地真实 Nginx 双站点实验：两套解释器各六条请求、四条线索，首两条分属不同站点未误凑窗口，实时与回放一致，容器移除、端口无监听。固定响应，不读真实敏感文件，不请求外站，不自动拉镜像。

两套解释器各运行60秒受控追加：每轮300条有效记录、一条坏行、两次文件代次切换、一次路径缺失及恢复；完整拼接后各回查到300条记录。实际墙钟分别60.109秒/60.096秒，分片74/82片（周期status数量不同，不要求分片数相同）。报告均为事件完整、分析有缺口，明确标记input_format_errors、rotation_requires_review、source_unavailable_during_run，不把异常隐去后宣称无缺口。该负载由真实采集模板生成，属于合成持续追加，不冒充生产请求或真实持续HTTP流量。

当前测试清单115项；发布门禁要求源码/中文路径解压树×Python3.11/3.15四轮完整执行、0跳过（含两个显式Docker集成），并核对跨cwd回放/报告/索引/时间线/分片拼接及逐文件哈希。精确运行输出与最终结果保存在开发机acceptance/v3.0.0-release/verification.json和对应txt，不随源码包携带。早期preflight旧版本断言失败记录保留，不能把它当最终通过输出。

独立只读复核覆盖第三版接入/隔离/索引及运行收尾；发现拼接最终buffer flush/close异常未清理部分输出后，增加故障注入回归并修复；过迟记录也补充analysis_gap健康提示。此为有限范围代码复核，不等于全面安全审计。

## 限制

- 正常多页面可能命中窗口，未给生产准确率或恶意判定。
- 有限乱序/容量会导致行为覆盖缺口，需看质量与摘要。
- 不保证输入轮转无损、exactly-once、跨运行断点恢复或断电完整性。
- 分片 manifest 元数据随片数增长，不是无限期恒定内存/磁盘服务。
- 短时连续运行不是多小时生产稳定、吞吐或 RSS 评估；历史 tracemalloc 基线不是 RSS。
- SQLite 是可重建派生物，实时/回放可能重复观察；原始日志/事件独立留证。
- 本地保留原文不强制脱敏，公开真实资料另行复核。旧分享功能不适配新事件格式。
- GitHub 上传/Release 创建由操作者执行，本地交付不代表远端已经发布。
