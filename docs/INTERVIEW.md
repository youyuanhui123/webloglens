# 演示与面试材料

## 演示顺序

1. python analyze.py --version：说明版本和运行环境，无第三方依赖。
2. python analyze.py examples/synthetic_burst.log --data-kind synthetic：解释统计与两类线索。
3. python run_experiment.py：生成三组真实本地 HTTP 实验，不用手编日志冒充结果。
4. 打开新实验目录 REPORT.md，再打开 mixed/analysis.md，按行号核对 access.log。
5. 对比 normal-wide：所有路径是正常页面，仍触发多路径规则，说明判断边界。
6. 展示 mixed/share.md 与完整报告差异，说明证据保留和公开分享是两种用途。
7. python -m unittest discover -s tests -v：展示可重复测试，不背诵固定输出。

## 应能解释的问题

- 为什么不能将 200 等同于泄露成功？响应可能是统一页面，访问日志通常没有完整响应体。
- 为什么按 IP 聚合有局限？NAT、代理与共享出口会合并多人，IP 也不能直接证明操作者身份。
- 为什么用滑动窗口？避免按整分钟切块漏掉跨边界的短时间事件。
- Counter 为什么不能只用 set 替代？请求过期时需要知道该路径在窗口中是否还有其他引用。
- 为什么保留 raw 与行号？便于回查证据，但脱敏分享版应移除 raw，原日志另存。
- 为什么先不解码 URL？必须定义解码与规范化语义，防止改变证据；同时如实承认编码变体漏报。
- 为什么配置错误不自动回退？静默改变规则会导致错误结果与不可复现。
- 为什么有正常多页面场景？用于实证阈值的非充分性，不只测试能命中的正样例。
- 分享版为什么不是匿名化保证？数量、关系和行号仍可能被关联。
