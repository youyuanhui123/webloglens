# 演示与项目表达（2.0.0）

## 五分钟演示（CMD，项目根）

```cmd
python analyze.py --version
python watch.py examples/synthetic_sensitive.log --replay --min-paths 3 --output docs/interview-events.jsonl
python report_events.py docs/interview-events.jsonl --output docs/interview-stage.md
python -m unittest discover -s tests -v
```

输出名必须不存在。先说明合成样例，再打开阶段报告：5条请求、2条精确路径线索、1条窗口线索，回查原文/偏移。然后展示normal-wide正常多页面也会触发窗口的受控实验，说明规则不是恶意标签；可选运行run_nginx_experiment.py真实采集，不把手写日志称为Nginx采集。

## 可以如实描述的项目

项目：WebLogLens——支持历史回放与实时跟随的Web访问日志排查工具（个人实践，AI辅助开发）。

围绕本地combined日志实现新增完整行跟随、有限乱序增量检测、迟到/容量缺口事件、文件原顺序回放与私有JSONL留存；从保存事件独立核对并生成阶段报告。设计本地原生Nginx正常、混合与正常多页面对照实验，验证线索和清理流程；建立受控合成资源与实际watch短时延迟基线，并以回归测试及解压搬迁验收保证可复现。

只有自己理解并能复现的部分才用“实现”；主要由AI编码时可说“参与设计并复现”。不得包装为客户项目、生产部署、独立原创漏洞或高准确率检测系统。展示工具能力与证明个人掌握程度是不同事情。

## 应能解释的取舍

- 为什么保留analyze？历史全量排序与现场增量观察互补，replay的有限乱序策略不能冒充全量排序。
- 为什么不每秒重扫？重复计算随文件增长，还会重复出线索；增量读取与有限状态解决的是连续运行问题。
- 为什么容量到顶要报事件？限制资源必然可能牺牲覆盖，不能把排除记录默认为安全。
- 为什么事件完整仍有缺口？迟到/超限诊断也可以完整保存，完整性不等于所有请求都参与了行为分析。
- 为什么原始target不自动解码？保留证据语义；代价是编码变体不自动等价。
- 为什么200不证明泄露？缺响应内容和应用上下文；404也不抹去探测事实。
- 为什么IP不是攻击者身份？NAT、代理和共享出口会合并多人。
- 为什么有normal-wide？正常行为可能达到阈值，不能只展示能命中的正例。
- 为什么新报告不直接分享？安全渲染不等于脱敏，新增字段未进入旧分享允许列表。
- 如何理解基线？Python分配峰值不是进程RSS，短时40样本的精确路径延迟不等于生产SLA或行为等待时间。

## 说清局限

仅单本地文件/固定combined，尚无远程多机、可信代理归因、强断点恢复、生产精度评估或多小时稳定性验证。不自动封禁，不判定入侵成功，不为作品包装无限扩功能。后续方向应依据实际岗位要求选择，而非继续堆规则名。
